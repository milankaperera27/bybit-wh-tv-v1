5. Android Dashboard & Human-in-the-Loop (HITL) Workflow
The mobile interface operates as an installable Progressive Web App (PWA) / Capacitor Android package. When a signal
satisfies validation criteria, it is held in Redis with a 60-second TTL . A high-priority FCM notification triggers actionable
buttons on the Android device, allowing the trader to review the entry, risk amount, and regime before routing. 
1-Tap Confirmation State Machine
1. Webhook received → Validated → Status PENDING_APPROVAL  → Redis TTL started.
2. FCM Push Notification dispatched with buttons: [Confirm Tradovate], [Route Kraken], [Reject].
3. If user taps Confirm → Execution bridge verifies risk limits, signs order, routes to venue API, and logs transaction.
4. If user taps Reject or 60s expires → Order transition to EXPIRED/CANCELED . Zero broker interaction.

# Kraken HMAC-SHA512 Signature Generator
import time, base64, hashlib, hmac, urllib.parse
def kraken_sign(urlpath: str, data: dict, secret: str) -> str:
    postdata = urllib.parse.urlencode(data)
    encoded = (str(data['nonce']) + postdata).encode()
    message = urlpath.encode() + hashlib.sha256(encoded).digest()
    mac = hmac.new(base64.b64decode(secret), message, hashlib.sha512)
    return base64.b64encode(mac.digest()).decode()
