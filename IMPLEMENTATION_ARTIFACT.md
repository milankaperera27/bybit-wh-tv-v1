## 3. FROZEN CONTRACT A — TradingView webhook payload

Emitted verbatim by `Atlas_Execution_Suite.pine`, parsed by `api/v1/webhooks.py`.

```json
{
  "token": "SECRET_TOKEN",
  "symbol": "NQ1!",
  "venue": "TRADOVATE",
  "action": "BUY",
  "limit_price": 20155.25,
  "stop_loss": 20140.00,
  "take_profit_1": 20178.12,
  "take_profit_2": 20201.00,
  "regime": "BULL_TREND_EXPANSION",
  "risk_pct": 1.0
}
```

* `venue` ∈ `TRADOVATE | KRAKEN`
* `action` ∈ `BUY | SELL`
* `regime` ∈ `BULL_TREND_EXPANSION | BEAR_TREND_EXPANSION | RANGE_COMPRESSION | VOLATILITY_CHOP`
* Transport auth: `X-Atlas-Signature: sha256=<hex hmac of raw body>` **or** the
  in-body `token` (constant-time compare). Body HMAC wins when both present.

## 4. FROZEN CONTRACT B — Backend REST surface

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/api/v1/webhooks/tradingview` | ingest alert → `PENDING_APPROVAL` + FCM |
| `GET`  | `/api/v1/confirmation/pending` | list live (unexpired) setups |
| `GET`  | `/api/v1/confirmation/{signal_id}` | single setup detail |
| `POST` | `/api/v1/confirmation/{signal_id}/confirm` | body `{"venue":"TRADOVATE\|KRAKEN"}` |
| `POST` | `/api/v1/confirmation/{signal_id}/reject` | transition → `REJECTED` |
| `POST` | `/api/v1/emergency/kill` | engage global kill switch |
| `POST` | `/api/v1/emergency/release` | disengage kill switch |
| `POST` | `/api/v1/emergency/flatten` | cancel working + flatten all venues |
| `GET`  | `/api/v1/emergency/status` | kill-switch + daily drawdown state |
| `GET`  | `/api/v1/health` | liveness/readiness |
| `WS`   | `/ws/dashboard` | live regime + pending-setup stream |

Mock/paper mode: when `ATLAS_MOCK_BROKERS=true` both broker clients build and
sign real payloads but short-circuit the network call, returning a deterministic
mock response. This is what LAYER 8 asserts against.

## 5. State Machine (spec §5)

```
  webhook ──validate──▶ PENDING_APPROVAL ──(Redis SETEX 60)
        │                    │
        │  tap Confirm/Route │  tap Reject          60s elapse
        ▼                    ▼                          ▼
     CONFIRMED ──risk ok──▶ ROUTED ──fill──▶ FILLED   EXPIRED
        │                                              (zero broker interaction)
        └──risk breach──▶ REJECTED_RISK
```

## 6. Acceptance Gates (LAYER 8)

1. `test_tradovate_bracket.py` — payload contains `accountSpec`, `accountId`,
   `action` capitalised, `symbol`, `orderQty`, `orderType`, `price`,
   `isAutomated: true`, `bracket.stopLoss`, `bracket.takeProfit`; Bearer header set.
2. `test_kraken_signature.py` — `kraken_sign` reproduces the canonical Kraken
   API reference vector byte-for-byte; `AddOrder` body carries `leverage`,
   `oflags=fcib`, `close[ordertype]=stop-loss`, `close[price]`.
3. `test_webhook_flow.py` — HMAC reject on bad signature, `PENDING_APPROVAL` on
   good, expiry yields zero broker calls.
4. `test_risk_engine.py` — position sizing, max-contract clamp, daily drawdown lockout.
